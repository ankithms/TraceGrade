# API Contract

Base path: `/api/v1`

JSON is used for requests and responses. Timestamps are UTC ISO 8601 strings. IDs are UUIDs. The OpenAPI document generated by FastAPI is the executable reference; this file defines the frozen resource surface before implementation.

## Authentication

- Admin operations: `X-TraceGrade-Admin-Key: <admin-key>`.
- Project operations: `Authorization: Bearer <project-api-key>`.
- Health endpoints require no authentication.

Project API keys are returned once at creation. All project-scoped resource IDs are checked against the authenticated project.

## Response Conventions

- Create: `201 Created`, except experiment start which returns `202 Accepted`.
- Read/update: `200 OK`.
- Delete/revoke: `204 No Content`.
- Validation: `422 Unprocessable Entity`.
- Authentication: `401 Unauthorized`; cross-project or unknown resources return `404 Not Found`.
- Conflict/idempotency mismatch: `409 Conflict`.

Errors use:

```json
{
  "error": {
    "code": "stable_machine_code",
    "message": "Human-readable summary",
    "request_id": "uuid"
  }
}
```

Collection endpoints accept `limit` (default 50, maximum 100) and `offset` (default 0) and return `{ "items": [], "total": 0 }`.

## Traces and Spans

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/traces` | Idempotently create or update a trace by `external_id`. |
| `GET` | `/traces` | List traces for the authenticated project. |
| `GET` | `/traces/{trace_id}` | Read a trace with spans. |
| `POST` | `/traces/{trace_id}/spans` | Idempotently create or update one span. |
| `POST` | `/traces/{trace_id}/spans/batch` | Ingest an SDK batch. |

Payloads expose the trace/span fields in `docs/db-schema.md`. Batch requests contain at most 100 spans and return accepted IDs plus item-level validation errors.

Single-resource ingestion and trace list/detail endpoints are implemented.
Batch ingestion is planned for the next branch.

Trace browsing uses the same project Bearer API key:

- `GET /traces?limit=50&offset=0` returns `{ "items": [...], "total": N }`.
  Only the authenticated project's traces contribute to items and total. Traces
  are ordered by ingestion time descending, then UUID descending to break ties.
  List items include trace metadata, without span payloads.
- `GET /traces/{trace_id}` returns the trace fields plus a `spans` array, ordered
  by start time ascending, then UUID ascending. The array is flat; each span's
  `parent_span_id` identifies its parent so clients can reconstruct the hierarchy.
  All input/output, model, metric, status, error, and attribute fields are retained.
- Unknown and cross-project trace IDs both return `404 trace_not_found`. An empty
  project returns an empty list with total zero; a trace without spans returns
  `"spans": []`.


- Send a project API key as `Authorization: Bearer <key>`. The server sets project
  and resource UUIDs; `project_id`, `id`, and unknown request fields are rejected.
- First delivery returns `201`; repeated delivery or an update returns `200`
  with the same resource UUID. External IDs are unique within a project.
- Requests are full snapshots. `name` and `started_at` identify the operation and
  cannot change when reusing an external ID. A span also retains its trace, kind,
  and parent. Identity changes return `409 idempotency_conflict`.
- Running records can be updated and completed with `ok` or `error`. Completed
  records accept identical replays; different final data returns `409`. A late
  running snapshot returns the completed record without changing it.
- Create a parent span before its children. A parent must belong to the same trace
  and project; missing or inaccessible traces/parents return `404`. Immutable
  parent links prevent callers from creating ancestry cycles.
- Timestamps require a timezone and are normalized to UTC. If supplied, `ended_at`
  cannot precede `started_at`.
- Serialized UTF-8 JSON is limited to 16 KiB for attributes and 64 KiB each for
  span input/output. Non-finite JSON numbers are rejected. Error messages are
  limited to 4,096 characters. Token counts and latency are non-negative 32-bit
  integers; cost is non-negative with at most 10 decimal places and 10 integer
  digits.

Example trace request:

```json
{
  "external_id": "review-123",
  "name": "AI Code Reviewer",
  "status": "running",
  "started_at": "2026-10-08T10:00:00Z",
  "attributes": { "pull_request": 123 }
}
```

Use the returned trace `id` with `POST /traces/{trace_id}/spans`:

```json
{
  "external_id": "review-123-model",
  "name": "Model call",
  "kind": "llm",
  "status": "ok",
  "started_at": "2026-10-08T10:00:01Z",
  "ended_at": "2026-10-08T10:00:02Z",
  "input": { "prompt": "Review this diff" },
  "output": { "summary": "Review complete" },
  "model": "example-model",
  "prompt_tokens": 20,
  "completion_tokens": 10,
  "total_tokens": 30,
  "latency_ms": 1000
}
```

## Evaluators

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/evaluators` | Create an exact-match, contains, JSON-match, or Gemini-judge evaluator. |
| `GET` | `/evaluators` | List evaluators. |
| `GET` | `/evaluators/{evaluator_id}` | Read validated configuration. |
| `PATCH` | `/evaluators/{evaluator_id}` | Update future-use configuration. |
| `DELETE` | `/evaluators/{evaluator_id}` | Delete an evaluator not used by a running experiment. |

Gemini-judge configuration stores a rubric and score/pass criteria. It does not expose provider routing or a prompt-management system.

## Experiments and Results

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/experiments` | Snapshot configuration and start a Temporal workflow; returns `202`. |
| `GET` | `/experiments` | List experiments, filterable by status/dataset. |
| `GET` | `/experiments/{experiment_id}` | Read status and aggregate progress. |
| `GET` | `/experiments/{experiment_id}/results` | List case-level results and evaluator scores. |
| `POST` | `/experiments/{experiment_id}/cancel` | Request cancellation of a non-terminal workflow. |

`POST /experiments` requires `dataset_id`, `name`, `version_label`, application execution configuration, and one or more `evaluator_ids`. Repeating the same request with the same client `idempotency_key` returns the existing experiment.

## Comparisons and Regressions

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/comparisons` | Compare completed baseline/candidate experiments and persist regression decisions. |
| `GET` | `/comparisons` | List prior comparisons. |
| `GET` | `/comparisons/{comparison_id}` | Read metrics, deltas, thresholds, and regressions. |

Comparison input contains `baseline_experiment_id`, `candidate_experiment_id`, and thresholds for quality decrease, latency increase, and cost increase. Both experiments must belong to the authenticated project and be complete.
